# 每日一道雅思口语：自媒体作品流水线

Bruce 于 2026-10-10 启动这一独立内容实验，允许复用已有音频或调用现有语音 API。
每天北京时间 18:00 准备一份本地作品包，由 Bruce 在抖音发布。第一轮试发七期。
这份交接执行本次新授权的四步短视频实验，不宣称 B04 历史双主持教学方案已完成。

## 两种输入，共用一个出口

- **全自动**：选一道有题源的题，Agent 编写自然、简短的示范中文与英文。
  示例经历可以由 Agent 编写，但明确标为“原创示范”，不冒充 Bruce 的真实回答。
- **本人回答**：先给 Bruce 题干、话题和题源；收到中文、英文或转写后保留原话，忠实改写。
  个人回答不能新增经历；不同于示范的正确说法不判错。有新回答时优先制作。

没有新的本人回答时，全自动任务照常完成，不因为等待回答而停产。
每次完成时再附一道下一期候选题，Bruce 可在本聊天中回答；不回复也不影响次日产出。
自动稿与本人稿分别记录 `answer_origin`，已完成自动稿不因后来收到本人回答而被覆盖。

## 每次生产的五步

1. **选题**：读根 AGENTS 和三份核心文档，再读 QUALITY_PLAYBOOK 与
   `skills/ielts-audio/SKILL.md`。检查 `output/` 的成品记录，避免重复题。
   只从 `data/question_bank_public.json` 的 Part 1 开始，优先当前考季和日常有共鸣的话题。
   本人输入优先；无输入时优先可用的已有音频，语句不自然或过长时编写新示范。
2. **编稿**：首轮通常 35–55 个英文词、两至四句，一个清楚的观点或小细节。
   中文与英文逐句对应；一至三个重点表达，必须在答案中出现，各给一个新场景例句。
   不机械填入高级词或口头禅，不写“必得 8 分”等承诺。已有音频的英文必须原样保留；
   需要改稿就生成新条目和新音频，不能沿用旧声音。
3. **音频与学习材料**：复用音频时只读源条目。新稿通过现有 library 的
   `get_or_create_topic` / `create_item` 接口建独立条目，保存 question / chinese /
   original_answer，原创稿放“自媒体原创示范”话题并保留示例性质。
   Agent 产出三份英文 JSON，执行 `pipeline.py complete` 的 canonical 命令；
   不读、打印或直传 Key，不直接调用 provider。真实合成已获本会话授权，
   每日只制作一题，最多两次完整合成尝试，不批量试音；失败保留输入并报告。
   为本人回答另执行 `pipeline.py study` 准备逐句学习材料，可从现有应用学习。
   文本由 Agent 编写，不额外调用付费文本模型。
4. **导出**：将内容计划写入忽略的 `output/inputs/日期.json`，调用下方 build 命令。
   四张卡片顺序为中文开口、盲听、英文揭示、表达迁移。卡片 1080×1440；
   竖屏视频 1080×1920，中间有两遍问答音频，盲听阶段不放答案字幕。
   原音频已自然且语速合适时传 `--speed 1`；语速过快可降到 0.82，避免过度变速。
5. **交付**：查看四张图与视频关键帧；检查中文英文意义、字号、裁切、阶段顺序、
   音频非静音、响度和时长。QA 不等于听感；真实声音的自然度与平台显示由 Bruce 抽听。
   成品是四张 PNG、MP3、MP4、发布文案、题源与校验记录、ZIP 和本地预览。
   只有校验通过才报告“作品包已生成”。不登录或自动发布到抖音，不上传外部服务。

## 题源与日期的准确写法

`question_id` 锚定本地公开题库中的真实记录，导出器校验题干、话题、考季标签。
现有记录有 2026 年 1–4、5–8、9–12 月标签；其中 9–12 月扩展题的仓库来源记录
为麦门雅思整理件。它们是本地整理记录，不自动等于当季官方真题。

默认显示“本地题库标签：2026年9–12月；考季未作当季独立核验”。
不能从季节标签推导“10 月考场真题”；发布日期与题目所属考季分别记录。
没有考季记录就显示“考季未核实”。需要“最新考季”认证时，先查可追溯的原来源，
保存 URL、发布日期与核验日期，区分官方样题与考生回忆题；来源不足就保留未核验措辞。
只抽取必要题干，中文提示、英文回答、例句、图卡与文案自行编写，不照搬第三方整篇答案。

IELTS 官方练习入口：<https://ielts.org/take-a-test/preparation-resources/sample-test-questions>。
官方对自然回答与避免机械背诵的建议：
<https://ielts.org/news-and-insights/dont-overdo-it-how-to-ace-your-ielts-speaking-test>。

## 内容计划 JSON

```json
{
  "question_id": "题库中的原始 ID",
  "headline": "中文封面标题，可用换行",
  "answer_origin": "原创示范",
  "sentences": [{"en": "音频中 B 回答的英文原句", "zh": "对应中文"}],
  "chunks": [{"en": "答案中出现的表达", "zh": "中文意义", "example": "新场景英文例句"}],
  "transfer_zh": "最后一个可以开口回答的迁移问题"
}
```

`answer_origin` 只允许“原创示范”“本人回答”“已有回答”。题干、Part、话题与考季
由导出器从题库读取，不能由稿件自行编造。逐句英文连起来必须等于 B 回答。

```bash
.venv/Scripts/python workflows/daily-ielts/build.py \
  --lesson workflows/daily-ielts/output/inputs/2026-10-11.json \
  --item-dir "data/topics/独立话题/items/目标条目" \
  --out workflows/daily-ielts/output/2026-10-11
```

输出必须在 `output/` 内，且目录不存在。完成后写 `verification.json` 的 `ready: true`；
当天有完整作品则直接交付链接，不重复生成或消耗 API。重新制作使用新的版本目录。
输入、本人语料与全部成品保持本地，不暂存或推送。每日只跑内容流程，不修改产品代码、
不更新产品里程碑、不发布 APK 或 Release。导出器改动才跑相关测试与完整工程门禁。

## 首轮观察

作品记录题目和格式；Bruce 发布后可回填播放、听完、收藏、关注和有效口答评论。
优先比较“收藏/播放”“新增关注/播放”和是否有人实际表达，不用单篇点赞判断长期效果。
先试七期，再用真实数据决定选题、时长和是否加入慢速跟读；不预设涨粉结果。

本地定时任务需要电脑开机且 Codex 应用运行；休眠或关机时不能保证准点生成。
调度边界参见 <https://learn.chatgpt.com/docs/automations?surface=app>。
