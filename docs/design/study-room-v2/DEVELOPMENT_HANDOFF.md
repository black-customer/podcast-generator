# 后续开发交接：从概念图到可用学习模式

这里记录后续 Agent 可直接采用的产品行为和实施顺序。图片与交互是目标状态，
本次提交本身未改产品前端或服务端。

## 当前真实能力

- 原始输入由 `original_answer` 保存；Agent/API 生成三份英文文本，音频完成后可播放。
- 精听播放器已有句级或词级时间轴；时间轴可能来自实测或估算，不能无条件精准截取单词。
- Web 与 Android 共用现有前端；离线包当前以音频、文稿与时间轴为主。
- `pipeline.py complete` 和 canonical `skills/ielts-audio/SKILL.md` 当前仍要求三份英文文本。
- 逐句中文、逐句讲解、录音历史、句子库和暖纸 UI 均尚待开发。

## 实施顺序

1. **学习材料真相层**：在原始回答不丢失和音频先可听的前提下，生成完整原意、逐句中文
   与英文对应、文本讲解、有原话依据的错误分析。数据保持本地、可读、可编辑。先定义校验与
   旧条目回退，再扩展 Agent/API 接口；旧三英文契约在迁移期间仍能完成音频。
2. **音频与材料绑定**：每句定位到实际播放文稿和音频版本。文本变更使相关学习材料待复核，
   音色改变不抹去用户已完成的学习记录。估算时间轴时退回安全的整句／更长片段播放。
3. **桌面学习 UI**：按 `B01–B10` 和 `S01–S06/S08` 实现逐句全句默写、讲解和三类录音。
   恢复草稿、提示计时、键盘输入和权限失败必须跟着主路径一起完成。
4. **句子复习与语料包**：按 `B11–B14` 和 `S07` 完成错句／提示／收藏记录；扩展离线包
   时处理旧包兼容、私有录音默认不导出、手机端写入与进度边界。
5. **视觉落地与验收**：全应用组件按 `VISUAL.md` 的颜色与层级统一；截图与图片逐页比对。
   只有运行中的页面才做真正的桌面 E2E，后续再设计手机学习布局。

## 每张图怎么读

- [catalog.json](catalog.json) 给出编号、入口、用户动作、下一状态、完整生图提示与图片文件。
- [INTERACTIONS.md](INTERACTIONS.md) 决定操作、结果和异常；[EXAMPLE_CONTENT.md](EXAMPLE_CONTENT.md)
  决定示例题、中文、英文与词框数量；[VISUAL.md](VISUAL.md) 决定色彩、排版和组件。
- `A05/A12/A13/B02/B04/B07/B08/B14/S07.html` 与 [reference.css](reference.css) 是九张
  修订概念图的可编辑静态来源，均不连生产 API。
- ImageGen 图上的英文/中文文案若与文字规范不一致，按文字规范实现；图的布局可作为参考。

## 必须检验的行为

- 中文／英文／混合输入保留原话，不能凭中文凭空列出「你原来写错的英文」。
- 音频可听而讲解仍在准备时，两个状态分别正确；失败不损失已完成音频。
- 所有句子按序出现，词框数与英文一致；答案只在用户主动提示或提交后出现。
- 提示隐藏不清空文字；用过提示后的正确提交仍保留提示记录。
- 拼写错误可定位；另一种合理表达不因与示范不同被直接定性为英语错误。
- 三类录音均可回听，重录保留历史；权限或保存失败能明确恢复。
- 退出恢复到上次位置，错句／提示句／收藏句进入复习；旧语料和旧包仍能播放。
- `bash scripts/check.sh` 全绿后再提交功能；未来实际 UI 要通过桌面和移动端截图检查。

本次设计里示例分钟数、播放时长与练习结果是合成内容。实际开发必须显示用户真实数据；
自动语义评分、ASR 发音评分与雅思分数不在现有能力范围内。
