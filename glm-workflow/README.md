# glm-workflow：单题速通工作流（Question Coach）

> 分支：`glm-workflow`（GLM 专属实验线）。**不改主产品任何工作流**：不碰 `data/`、
> `server/`、`web/`、`pipeline.py`、`skills/ielts-audio/`。其他 Agent 的平行实验线
> 互不干扰，验收后由 Bruce 决定是否合入。
>
> 与主线的分工：主线（ielts-audio）解决"把我的回答变成母语者音频，反复听"；
> 本工作流解决"针对**一道具体题目**，用最小剂量的材料把这道题打穿"。

## 0. 设计第一原则：反压倒性（Anti-Overwhelm）

bruce_kit 一期的教训：7 条音频 + 22 张卡覆盖面太广，学习者"想学的太多于是不想学了"。
本工作流的交付物有**硬性上限**，任何一项超限都视为违规产出：

| 项目 | 上限 | 原因 |
|------|------|------|
| 音频 | **1 条**，90–240 秒 | 一次学习一个对象，能听 3 遍 |
| 错误修复 | **≤ 3 条**（每条必须有原句证据） | 只修这道题暴露的最高频伤口 |
| 语块 | **≤ 2 个**（15 秒内可复述） | 一次记 2 个 > 一次见 20 个（检索练习研究） |
| 卡片 | **4 张**（错误修补 1 + 语块 2 + 模范答案 1） | 手机壁纸轮播一天能看完 |
| 收尾物 | **1 页速览 HTML** | 所有内容一屏可达，不需要"学习计划" |
| 带走句 | **1 句** | 合上手机还能背出来的那句 |

## 1. 两阶段结构

**阶段一：单题教学包（核心，人人需要）**

```
输入：一道雅思口语题 + 学习者的原回答文本（语音转文字亦可）
  ↓ Agent 诊断与改写（判断性工作，见 §3 执行清单）
kit JSON（内容源，人类可读可改，唯一真源）
  ↓ generate_question_kit.py（确定性合成，见 §4）
输出：1 音频 + 4 卡片 + 1 页速览（全部落在一个题目目录里）
```

**阶段二：自媒体包装包（Bruce 专属可选项，开源用户默认关闭）**

在阶段一产物之上做**包装**，不新造知识点：
- 3 个候选标题（钩子公式见 §5）
- 纯英文双主持 45–60 秒短视频脚本（宪法 B04：纯英文双主持优先；中英结合变体可选）
- 1 张封面卡（1080×1440）
- 发布文案 + 标签（按平台）

## 2. 输入契约

- 必须同时有：题目原文（英文）+ 学习者回答原文。缺任何一项 → 停下要材料，不许脑补。
- 回答是语音转文字时：转写噪音（重复、口误、ASR 错词）不算学习者错误；
  只把**稳定复现或语义可辨识**的表达问题计入诊断。分辨不了的（如发音）不猜，明说。

## 3. Agent 执行清单（阶段一，判断性工作）

1. **校验输入**：题目 + 原回答齐备。
2. **诊断**：从原回答提取 ≤3 个错误修复 + ≤2 个语块。判据：
   - 错误修复：能在原文指出原句；错误类型是"零件装反"（语法/搭配/假朋友），不是"想法不对"；
     每条给出 `wrong / right / rule`，rule 一句话能懂。
   - 语块：优先选"能修他原句里卡住的那个意思"的块（如他说不出"设限制"，就教
     `set clear limits on`）；每个块给一个**迁移示范句**（换一个话题也能用）。
   - 学习者已经说对的（如 double-edged sword）：不占语块名额，在模范答案里自然复现即可。
3. **改写 8.5 分模范答案**：第一人称口语；**保留原回答的全部真实经历、观点、细节，
   不得虚构新事实**；长度 5–8 句；学习者已掌握的好表达自然复用；两个语块必须出现。
4. **带走句**：一句含核心语块的话，合上手机能背出来。
5. **填 kit JSON**（字段见 `demo_smartphones.kit.json`，含每字段的填写说明）。
6. **合成**：`.venv/Scripts/python glm-workflow/generate_question_kit.py --kit <kit.json>`
   （真实 TTS = Fish 免费档；按内容哈希缓存，重跑零成本续跑）。
7. **质量门**（全过才算交付）：
   - 音频时长 90–240 秒；-16 LUFS；恰好一条 8 秒检索静音（程序检查，生成器自动做）
   - 卡片过视觉验收（judge 子代理或逐张自查：无溢出/无断词/无豆腐块/无重叠）
   - 速览 HTML 用浏览器打开目检一遍
   - 自听门：音频交付 Bruce 抽听（最终听感由 Bruce 定，工程不阻塞）

## 4. 确定性合成（generate_question_kit.py）

脚本只做模板装配 + TTS + 出图，不做内容判断：
- 音频结构固定：`钩子→读题→2 组原句对比→2 个语块→8.5 分完整示范→提示音+8s 检索→带走句`
- 检索窗口提示音 660/880 Hz 与 bruce_kit 一期一致（学习者已建立条件反射）
- 卡片版式固定（与 bruce_kit 视觉体系一致）；模范答案卡中语块绿色高亮（分段渲染）
- 输出目录：`glm-workflow/output/<kit-id>/`（audio+cards+速览.html，gitignore）

## 5. 阶段二：自媒体包装规范（Bruce 专属）

- **标题钩子公式**（3 选 1 起抛）：具体题目 + 反共识立场 / 分数锚点（"8.5 分这样答"）/
  痛点场景（"考官问 X，中国考生 90% 第一句就输"）
- **脚本结构**（45–60 秒）：3 秒钩子（考官原声问句）→ 15 秒普通答案 vs 8.5 答案对比 →
  20 秒拆解 1 个语块（只拆 1 个！视频不是课）→ 10 秒带走句 + CTA（"你的答案打在评论区"）
- **宪法约束沿用**：任何一行台词纯单语；无笑声/呼吸标签；不求教会所有知识点，
  只求观众 15 秒内能复述带走句
- 封面卡：大字问题 + 一句反共识答案 + 分数徽章；先给想点进来的人一个"我需要"的瞬间

## 6. 开源展望（不阻塞当前）

他人复现路径 = 把题目 + 回答发给任何 Agent，附上本 README §3 清单 + kit JSON 模板即可。
无自媒体阶段、无 Bruce 个人材料依赖；server/tts 的 Fish 免费档与缓存机制随主仓开源。

## 7. 迭代记录

- **v1（2026-09-23）**：demo 题《Do you think children should have their own smartphones?》
  （回答取自 Bruce 真实转写）。首轮产出与修复见 git log 与下方规则固化。
- **规则固化**（每轮优化后追加，不删旧条目）：
  - R1 模范答案卡必须用流式分段渲染（语块高亮），否则长答案必溢出；
  - R2 音频对比段 ≤2 组——第 3 组开始学习者记忆收益骤降，塞进速览页即可；
  - R3 语块迁移示范句必须换话题（让学习者看到"这题之外我也在涨"）；
  - R4 转写噪音（ASR 错词、纯口误）不进诊断，防止学习者被冤枉；
  - R5 合成前必须静态走查台词块顺序（v1 曾把检索指令排到静音窗口之后——8 秒空白
    先于指令等于白给）；
  - R6 阶段二交付物（媒体包装包/封面）不得出现仓库内部术语（宪法编号、里程碑名），
    那是给外人看的作品，不是工作日志；
  - R7 TTS 网络不可用时用 `--skip-audio` 先出文字/图片产物迭代内容，音频后台重试补齐，
    绝不让网络阻塞内容工作；交付前重跑补音频并过质量门。
