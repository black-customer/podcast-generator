# one-question：一道题，一次吃透

这个工作流解决一件事：**用户给一道题和他的原始回答，系统自动产出一份他当场就能学完的教学包。**

它存在的理由是剂量。一次给 42 分钟音频和 35 张卡，人不会去学，只会关掉。
所以下面所有的"硬上限"不是建议，是这个工作流的全部意义。

## 输入契约

用户提供两样东西，其余全部由 Agent 推断：

| 必需 | 说明 |
|------|------|
| `question` | 题目原文（一道，不是一组）。若用户给的是连续几问，取最核心的一问，其余作为 follow_ups |
| `answer` | 用户本人的回答原文，**保留所有错误、口头禅、重复和自我修正**，不许先替他改 |

可选：`part`（1/2/3）、`target_band`（默认 7.5）。

## 硬上限（超了就报错，不许放宽）

| 维度 | 上限 | 为什么 |
|------|------|--------|
| 纠错点（fixes） | **3** | 第 4 个错误这一轮就不会被习得，只会稀释前 3 个 |
| 语块（chunks） | **3** | 一题只够把 3 个新表达推到自动化 |
| 示范答案 | **5 句 / 60–85 词** | Part 1 的真实长度；写长了就是阅读不是口语 |
| 音频总长 | **≤ 6:30** | 通勤一站地 |
| 强制输出窗口 | **6 个**，每个 8–10 秒 | 少于 6 次开口=没练；多于 10 次=累到放弃 |
| 卡片 | **3 张** | 答案卡 / 语块卡 / 前后对比卡，各一张 |
| 一轮学习时长 | **≤ 12 分钟** | 超过 12 分钟的事，人不会"今天就做" |

## 工作流（顺序执行）

### 1. 量化，不要凭感觉

```bash
.venv/Scripts/python scripts/one_question/diagnose.py --question "<题目>" --answer "<回答原文>"
```

输出的是**证据**：填充词率、模糊名词次数、让步连接词是否为 0、命中的语法化石及其原句、
平均小句长度、有没有"立场→理由→例子"结构。

这一步不能跳过。凭印象挑的 3 个错通常是最"显眼"的，不是**分数损失最大**的。

### 2. 写 lesson.json

按 `scripts/one_question/lesson.schema.json` 手写。要求：

- `fixes[].original` 必须是用户原话逐字（这是"注意到差异"的原料，改了就没用了）
- `fixes[].fixed` 只修那一处，不要顺手把整句重写成另一篇文章
- `model_answer` 的 5 个句子必须**同时用上全部 3 个 chunk**，且内容来自用户自己说过的经历
  ——不是编一个漂亮但跟他无关的示范
- 每个 `prompt_zh` 是一句中文，用于"中文→英语"的检索练习（比"跟我读"有效得多）
- 不许虚构用户没说过的经历

### 3. 构建

```bash
.venv/Scripts/python scripts/one_question/build.py lessons/<id>/lesson.json
```

产出：`lesson.json` 校验 → 音频 → 3 张卡 → `page.html`。
校验不过会列出具体是哪条超了上限，改 `lesson.json` 重跑，**不许改校验器放宽上限**。

### 4. 交付（固定格式，不要自由发挥）

只给用户三行：

1. **这一轮只练什么**：一句话，指出他这道题真正的失分点（引用诊断里的数字）
2. **现在做什么**：`page.html` 路径 + "点播放，窗口里必须出声"
3. **12 分钟后你会得到什么**：具体到能说出哪一句

不要罗列你生成了多少个文件。他不需要知道。

## 音频的五段结构（build.py 固定实现，不要改顺序）

```
① 钩子    考官念题目，2 秒后进入              ← 让他知道要答什么
② 差异    你的原话 → 正确版（紧挨着，不解释）  ← noticing
③ 规则    一句话规则 + 8 秒强制输出（中文提示） ← 检索练习
④ 示范    5 句答案，自然语速 → 逐句跟读        ← 自动化 + 节奏
⑤ 压速    考官再问一次，只给 4 秒              ← 迁移到考试节奏
```

第 ③ 段重复三次（三个 fix），第 ⑤ 段必须放在最后——**先给答案，再抽考**，
顺序反过来就变成听力练习而不是口语练习。

## 完成定义

- `diagnose.py` 跑过，lesson 里的判断有数字支撑
- 音频时长 ≤ 6:30，响度 −16 LUFS 附近，静音窗口数量对得上
- 3 张卡逐张看过图（不是"文件存在"就算过）
- 报告里给出实际运行的命令与结果，不说"应该没问题"

## 禁止

- 不读、不打印、不传输任何 API Key
- 不写 `data/`（那是产品语料库，会随可分享版打包给其他用户）
- 不在一轮里塞第 4 个纠错点
- 不把用户的错误原话"美化"掉——那是这个工作流的燃料

## 与相邻工作流的关系

- `ielts-audio`：批量"我的回答→地道英文→播客音频"，产出的是**语料条目**。
  本工作流产出的是**训练包**，不落 data/，不进播放器。
- `one-question-creator`（Stage 2）：在本工作流产物之上做自媒体包装。**可选**，
  只在用户明确要发布时才跑；开源分发时不包含它。
