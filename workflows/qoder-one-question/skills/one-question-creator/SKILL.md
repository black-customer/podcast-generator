# one-question-creator：把教学包变成一个别人愿意看的作品

Stage 1 解决「他学得完」。这一阶段解决「陌生人为什么愿意看完」。
两者对同一份内容要求完全不同，所以必须分开，不能混进一个流程里互相拖累。

**这一层是 Bruce 的私有能力，不进入开源包。** 别人的需求只有备考，没有涨粉。

## 前置

`lessons/<id>/` 已经由 Stage 1 产出（lesson.json + 三张卡 + 音频）。
没有音频就先跑 Stage 1；短片旁白直接复用教学音频里的钩子段和示范段，不重新合成。

## 一条内容只讲一个「啊哈」

Stage 1 一份教学包有 3 个纠错点。**发布时只能选 1 个。**
这不是保守，是短视频的物理规律：一条视频讲两个知识点，完播率和记忆率同时掉。
所以 creator 的第一步是**选点**，不是排版。

选点标准（按顺序淘汰）：

1. **陌生人在 3 秒内能自测**——他一听就知道自己也会这么说错（"I don't have kind of favorite teacher"）
2. **反差够大**——错的那句和对的这句听起来像两个水平的人
3. **不依赖上下文**——不需要知道雅思考什么也能看懂
4. 有画面感／好笑 > 语法精确

## 60–75 秒的结构（固定，不要发挥）

| 秒 | 内容 | 素材 |
|----|------|------|
| 0–3 | 钩子：直接把**错误原话**打在屏幕上，配一句"这句我听了 200 遍" | 封面/大字卡 |
| 3–12 | 演一遍错版：放他本人的错误句（TTS 念，不说是谁的） | audio 片段 |
| 12–30 | 给正确说法 + 为什么 | 答案卡 + 旁白 |
| 30–50 | 一个可迁移的语块，给 2 个别的题目里的用法 | 语块卡 |
| 50–65 | 压速：抛原题，留 3 秒安静，让屏幕前的人自己答 | 窗口静音 |
| 65–75 | 收口：一句"评论区把你的答案打出来" | 大字卡 |

留那 3 秒安静是**故意**的：观众开口（哪怕在心里）的那一条评论率显著高于纯观看。

## 产出物

```bash
.venv/Scripts/python -m one_question.creator lessons/<id>/lesson.json
```

- `cover_3x4.png`（小红书）、`cover_9x16.png`（抖音/视频号）——真实字体渲染，不用生图模型写字
- `short_script.json`——逐镜清单（时间、画面、字幕、音源），人和机器都能读
- `publish.md`——3 个标题候选（钩子型／反差型／搜索型）、正文、话题标签、发布时间建议
- `short.mp4`——1080×1920，有 audio.mp3 时才生成

## 可选：Minimax H3 动态开场

本地部署的 MiniMax H3（Hailuo 3.0）只用在**一个地方**：把封面图变成 3–5 秒有呼吸感的开场（图生视频）。

理由：文字必须清晰，而视频模型会糊字。所以文字部分永远由我们的 HTML 渲染提供，
模型只负责让画面动起来。口播数字人和全生成场景都**不用**——前者要露脸授权，后者废片率高。

```bash
set MINIMAX_BASE_URL=http://127.0.0.1:<port>     # 你自己起的服务
set MINIMAX_API_KEY=...                           # 不要写进文件
.venv/Scripts/python -m one_question.creator lessons/<id>/lesson.json --motion
```

`--motion` 在检测不到服务或调用失败时**自动跳过**，只留静态封面，不阻塞出片。
适配器在 `one_question/minimax.py`，按官方异步任务接口实现（提交 → 轮询 → 取 file_id → 下载）。

## 禁止

- 一条视频塞两个知识点
- 用生成模型渲染任何带文字的帧
- 把 Bruce 的真实姓名、学校、城市写进对外物料（`lesson.json` 里的私人细节只用于教学，发布文案要脱敏）
- 为了流量把示范答案改简单——观众里有人照着说，那是要进考场的
